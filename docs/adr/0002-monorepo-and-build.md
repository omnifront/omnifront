# ADR-0002: مونوریپو و ابزار بیلد

**وضعیت:** Accepted
**تاریخ:** 2026-11-07

## زمینه

پروژه چند پکیج مستقل (core، query، store و آداپترهای React/Vue/Angular/Next) دارد که باید جدا منتشر شوند ولی با هم توسعه و تست شوند. اندازه‌ی پروژه در نسخه‌های 0.x کوچک است.

## تصمیم

- مدیریت پکیج و workspace: pnpm 12 (فقط pnpm workspaces)
- بیلد: `tsup` برای هر پکیج (ESM + CJS + `.d.ts`)
- تست: Vitest
- انتشار: Changesets
- کنترل حجم: `size-limit` در CI (بودجه‌ی gzip: core ≤ 1KB، query ≤ 3KB، هر آداپتر ≤ 1KB)
- اجرای اسکریپت‌ها با `pnpm -r run <script>`؛ هر پکیج اسکریپت‌های خودش را دارد.

## گزینه‌های ردشده

- Turborepo و Nx: در این اندازه ارزششان را ندارند. بعداً با معیار بازبینی اضافه می‌شود.
- Rollup / Vite library mode: tsup ساده‌تر است.
- Jest: کندتر است و پیکربندی ESM دردسر دارد.

## پیامدها (مثبت و منفی)

مثبت: ابزار کم، پیکربندی ساده، هر پکیج مستقل از بقیه قابل بیلد است.
منفی: کش بیلد و تست وجود ندارد، پس با بزرگ‌شدن پروژه CI کند می‌شود. پکیج Angular ممکن است به pipeline بیلد جدا (`ng-packagr`) نیاز پیدا کند.

## معیار بازبینی

اضافه‌کردن Turborepo اگر: CI از حدود ۵ دقیقه بیشتر شد، بیلد docs/examples/Angular خیلی کند شد، یا تعداد مشارکت‌کننده‌ها زیاد شد. مهاجرت ساده است چون Turbo همان اسکریپت‌های هر پکیج را صدا می‌زند.
