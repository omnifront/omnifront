# ADR-0012: رابط کاربری devtools
**وضعیت:** Proposed
**تاریخ:** 2026-11-09

## زمینه

`@omnifront/devtools` امروز یک مدل بدون UI (`DevtoolsModel`) و یک پنل DOM خام (حدود ۱۶۰ خط) دارد: فهرست ورودی‌های کش، جزئیات، و دکمه‌های Invalidate و Cancel. برای کشی با ده‌ها ورودی کافی نیست (فیلتر، جست‌وجو، نمایش درخت داده، refetch ندارد). دو قید از ADRهای قبلی:

- ADR-0011 گفته بود اگر devtools بخواهد به‌جای polling از `onChange` استفاده کند، ADR بازبینی شود. مدل فعلی هر ۵۰۰ms کش را می‌خواند و حتی وقتی چیزی عوض نشده زمان‌سنج دارد؛ این معیار حالا فعال شده است.
- بودجه‌ی `query` پر است (۳۰۶۳ از ۳۱۰۰ بایت) و `/activity` روی ۹۰۳ از ۱۰۰۰ بایت است. هر چیزی که API پکیج `query` را بزرگ کند باید جدا تصمیم‌گیری شود.

«UI» در این ADR یعنی فقط همین پنل. افزونه‌ی مرورگر و devtools مخصوص هر فریم‌ورک (غیرهدف در CLAUDE.MD) بیرون از دامنه است.

## تصمیم

1. **پنل همان DOM خام درون shadow root می‌ماند** (بدون فریم‌ورک، بدون وابستگی تازه، متن همیشه با `textContent`). مدل بدون UI همچنان قرارداد (`Subscribable`) است تا افزونه‌ی آینده از همان استفاده کند.
2. **push به‌جای poll:** `DevtoolsModel` به `client.onChange` وصل می‌شود (ADR-0011). زمان‌سنج `interval` فقط برای فیلدهایی می‌ماند که رویداد ندارند (پرچم `observed`). قاعده‌ی «همان مرجع snapshot تا وقتی چیزی عوض نشده» (ADR-0001) حفظ می‌شود.
3. **ویژگی‌های پنل:** فیلتر متنی روی کلید (در پنل، نه مدل)، تراشه‌های وضعیت (fetching، error، invalidated، idle) با شمارش، مرتب‌سازی پایدار، نمایش جزئیات به‌صورت درخت قابل‌بازشدن، زمان نسبی `dataUpdatedAt`، کپی JSON.
4. **عملیات:** Refetch (از راه `invalidateQueries` با `exact`)، Invalidate، Cancel، و دو عمل سراسری «Invalidate all» و «Clear cache» (`client.clear()`). حذف تک‌ورودی (`removeQuery`) متد تازه روی `QueryClient` می‌خواهد و فعلاً انجام نمی‌شود.
5. **بودجه:** مدل ۱KB می‌ماند. بودجه‌ی `@omnifront/devtools/panel` از ۳KB به **۴KB** می‌رود (فقط با همین ADR). اگر ویژگی‌ها از ۴KB گذشت، یا ویژگی حذف می‌شود یا ADR جدید.
6. **تب Mutations (اختیاری، مرحله‌ی آخر):** نیاز به `mutationKey` و خواندن رجیستری `trackMutation` در `/activity` دارد. فقط اگر ADR جدا (یا اصلاحیه‌ی همین) هزینه‌ی بایتی `activity` را تأیید کند وارد می‌شود. تا آن موقع پنل فقط کوئری‌ها را نشان می‌دهد.

## گزینه‌های ردشده

- نوشتن پنل با React/Preact/lit: وابستگی تازه و قاعده‌ی «فقط آداپترها فریم‌ورک را import کنند» را می‌شکند.
- نگه‌داشتن polling: تأخیر ۵۰۰ms، کار بیهوده‌ی همیشگی، و ADR-0011 همین را بازبینی‌شدنی نامیده بود.
- افزودن `removeQuery` و `mutationKey` همین حالا: سطح API تازه در `query` برای نیازی که هنوز ثابت نشده.
- افزونه‌ی مرورگر در این فاز: غیرهدف در CLAUDE.MD؛ مدل بدون UI جا را باز نگه می‌دارد.

## پیامدها (مثبت و منفی)

مثبت: به‌روزرسانی فوری پنل، بدون زمان‌سنج وقتی کش ساکن است؛ پنل برای کش‌های بزرگ قابل‌استفاده می‌شود؛ هیچ تغییری در `query` لازم نیست چون `onChange` از قبل هست.
منفی: بودجه‌ی پنل +۱KB (فقط برای کسانی که در dev آن را import می‌کنند، و با شرط `DEV` از بیلد production حذف می‌شود)؛ رفتار fallback زمان‌سنج باید همچنان تست شود.

## معیار بازبینی

اگر `observed` هم باید فوری شود (نه با زمان‌سنج)، به رویداد روی `Query` نیاز است و ADR-0011 دوباره باز می‌شود. اگر Mutations یا `removeQuery` لازم شد، اصلاحیه‌ی همین ADR یا ADR جدید با حساب بودجه‌ی `query`/`activity` نوشته شود. اگر پنل از ۴KB رد شد، ویژگی حذف یا ADR تغییر بودجه.
